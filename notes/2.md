# K&R Chapter 2 — Types, Operators, and Expressions

## 1. Variable Names

- Must start with a letter or underscore; thereafter letters, digits, or underscores are allowed.
- Case-sensitive: `count` ≠ `Count`.
- Reserved keywords (`if`, `int`, `while`, …) cannot be used as identifiers.
- Avoid leading underscores — names beginning with `_` (especially `_` followed by an uppercase letter, or a double underscore) are reserved for the implementation. Collisions are undefined behavior, not always silent.

## 2. Data Types

### Basic types

| Type | Typical size | Notes |
|------|------|-------|
| `char` | 1 byte | Holds one character code or a small integer |
| `int` | ≥ 16 bits (commonly 32) | Whole number; matches the machine's natural word size |
| `float` | 32 bits | ~6–7 significant decimal digits |
| `double` | 64 bits | ~15–16 significant decimal digits |

Sizes above are typical, not guaranteed by the C standard except where noted under Qualifiers below — always check `<limits.h>` / `<float.h>` if it matters.

**`char` stores a number, not a letter.** `'A'` is `65`. ASCII maps 0–127 to characters; values above 127 are encoding-dependent — accented and non-Latin characters need multi-byte schemes (e.g. UTF-8) that a single `char` cannot represent alone.

**Precision** = number of significant digits stored accurately: `float` → ~7, `double` → ~15. More bits of mantissa = more decimal digits stored correctly.

> **[bare-metal — STM32F411]** Write `5.0f`, not `5.0`. Unsuffixed decimal constants are `double` by default. The STM32F411's FPU is single-precision only, so `double` arithmetic falls back to slower software emulation.

### Qualifiers

**`short` / `long`** — apply to `int` only.
- Guaranteed by the standard: `short` ≥ 16 bits, `int` ≥ 16 bits, `long` ≥ 32 bits, and `sizeof(short) ≤ sizeof(int) ≤ sizeof(long)`.
- Common case: `short` = 16 bits, `int` = 32 bits, `long` = 32 or 64 bits. On some embedded targets `short` and `int` may both be 16 bits.
- Style: write `long x`, not `long int x`.

**`signed` / `unsigned`** — apply to `char` and any integer type.
- `unsigned` *n*-bit range: 0 to 2ⁿ−1 (e.g. 8-bit: 0 to 255).
- `signed` *n*-bit range: −2ⁿ⁻¹ to 2ⁿ⁻¹−1 (e.g. 8-bit: −128 to 127) — one extra negative value because zero uses up one non-negative slot.
- Plain `char`'s signedness is implementation-defined, but this doesn't affect the ASCII printable range (0–127).

**`long double`** — extended-precision floating point; exact size is implementation-defined.

Valid combinations for floating-point types:

| Qualifier | with `float` | with `double` |
|-----------|:---:|:---:|
| `long` | invalid | ✓ → `long double` |
| `short` / `signed` / `unsigned` | invalid | invalid |

## 3. Constants

| Form | Type | Example |
|------|------|---------|
| Unsuffixed integer | `int` (or wider, if it doesn't fit) | `1234` |
| `l` / `L` suffix | `long` | `1234L` |
| `u` / `U` suffix | `unsigned int` | `1234U` |
| `ul` / `UL` (any case mix) | `unsigned long` | `1234UL` |
| Unsuffixed decimal or exponent form | `double` | `123.4`, `1e-2` |
| `f` / `F` suffix | `float` | `1.5f` |
| `l` / `L` suffix (on a decimal) | `long double` | `1.5L` |

**Character constants** — single quotes; an `int` value under the hood. `'A'` == `65` (ASCII).

**String constants** — double quotes; a `char[]` under the hood, null-terminated. `"hello"` occupies 6 bytes (5 characters + `'\0'`). `strlen()` from `<string.h>` returns the length *excluding* the terminating `'\0'`.

```c
'x'   // int     — the ASCII value of 'x'
"x"   // char[2] — {'x', '\0'}
```

Escape sequences (`\n`, `\t`, `\\`, …) are valid in both single- and double-quoted literals.

**Enumeration constants:**

```c
enum months { JAN = 1, FEB, MAR, APR, MAY, JUN,
              JUL, AUG, SEP, OCT, NOV, DEC };
/* FEB = 2, MAR = 3, … */

enum months day = FEB;
```

- The first enumerator defaults to 0; each subsequent one increments by 1 unless explicitly overridden. An unspecified value continues from the last explicitly given value.
- `enum months` is a type; `day` is a variable of that type.
- Advantage over `#define`: the compiler can type-check enum values; a macro is just blind text substitution.
- An enum's underlying values are integers — you can't store arbitrary types in it.

## 4. Declarations

1. A variable must be declared before use.
2. A variable may be initialized in its own declaration.
3. **Storage duration governs when initialization happens:**
   - **External / static variables** are initialized once, conceptually before `main()` runs. Their initializer must be a *constant expression*, because the OS loader writes the value into the program's memory image before any code executes — nothing is "running" yet to evaluate an arbitrary expression.
   - **Automatic (local, non-`static`) variables** with an explicit initializer are initialized *every time* their enclosing function or block is entered — this is ordinary executing code, so the initializer may be *any* expression, not just a constant one.
   - **Default values:** external and static variables are zero-initialized by default (guaranteed by the language). Automatic variables with no explicit initializer hold garbage — whatever bits were left on the stack by previous execution.
4. The `const` qualifier before a declaration means the variable's value cannot be changed after initialization.
5. For an array, `const` means its elements cannot be changed.
6. `const` can also qualify array/pointer function parameters, to document that the function does not modify the caller's data:
   ```c
   int func(const char a[]);   // won't modify the array contents
   int func(const int a);      // a is passed by value anyway — const here just
                                // prevents func from reassigning its local copy
   ```

## 5. Arithmetic Operators

1. Binary operators: `+`, `-`, `*`, `/`; `%` is the modulus (remainder) operator — `%` is not valid on `float`/`double`.
2. Integer division truncates any fractional part (truncation is toward zero).
3. Precedence, highest to lowest:
   - **a. Unary `+`, unary `-`, unary `!`** — e.g. `-5`, `+8`, `-x`.
     `!` (logical NOT) maps a non-zero operand to `0`, and a zero operand to `1`. Common idiom:
     ```c
     if (!valid)   // equivalent to: if (valid == 0)
     ```
   - **b. `*`, `/`, `%`**
   - **c. `+`, `-`**
   - Operators at the same precedence level are evaluated left-to-right.

---

## 6. Relational and Logical Operators

- **Relational:** `>`, `<`, `>=`, `<=` — all the same precedence; left-to-right is the tiebreaker.
- **Equality:** `==`, `!=` — lower precedence than relational operators, but *higher* than assignment (`=`).
- **Logical:** `&&`, `||` — evaluated left-to-right with **short-circuit evaluation**: evaluation stops as soon as the overall truth value is determined. `&&` binds tighter than `||`.

**Overall precedence (highest → lowest):** Unary → Arithmetic (`* / %` then `+ -`) → Relational → Equality → `&&` → `||` → Assignment.

> Example: `i < a - 1` parses as `i < (a - 1)`, since arithmetic binds tighter than relational.

## 7. Type Conversion

Operator with operands of different types are involved they are converted to a common type - it is called type conversion. It follows some rules.
- In general, the only automatic conversions are those that convert a "narrower" type to a "winder" one, without losing information.
eg. converting an integer into a floating point, in an expression like f + i.
- expressions that might lose information, may draw warnings but are not illegal.
eg. assigning long int to short, or assigning floating-point type to an integer (this is narrowing conversion).
- A char is just a small integer, so chars may be freely used in arithmetic expressions.
