## 1. Variable Names

- Must start with a letter. After that: letters, digits, underscores. Case-sensitive (`count` ≠ `Count`).
- Reserved words (`if`, `int`, `while`, etc.) can't be used as names.
- Don't start names with underscore — the standard library already uses those internally. Collision causes a silent bug.

## 2. Data Types

### Basic types

| Type     | Size    | Stores |
|----------|---------|--------|
| `char`   | 1 byte  | one character, or a small integer (0–255) |
| `int`    | varies  | a whole number, sized to what the machine handles best |
| `float`  | 32 bits | decimal number, ~7 significant digits |
| `double` | 64 bits | decimal number, ~15 significant digits (more precise) |

**`char` stores numbers, not letters.** Under the hood, `'A'` is just `65`. ASCII maps numbers 0–127 to characters. Values above 127 are encoding-dependent — umlauts, accented letters, etc. need multi-byte schemes (UTF-8) that plain `char` alone can't handle.

**float vs double — what's "precision"?** It means how many significant digits you get. `float` is 32 bits and gives ~7. `double` is 64 bits and gives ~15. More bits = more decimal places stored accurately.

> **[bare-metal]** Write `5.0f` not `5.0`. Unsuffixed decimals are `double` by default. The STM32F411's hardware only does single-precision (`float`) — `double` gets emulated in software and is much slower.

---

### Qualifiers

**`short` / `long`** — applies to `int` only. Changes the size.
- C only guarantees: `short` ≥ 16 bits, `long` ≥ 32 bits, and `short ≤ int ≤ long`. Exact sizes depend on the compiler/machine.
- Drop the `int`: write `long x`, not `long int x`.
- C only guarantees short ≤ int. On most modern machines, short is 16 bits and int is 32 bits — different. But on some older or embedded systems both could be 16 bits — same. So short may or may not be smaller than int, but is neccessarily not bigger than int.

**`signed` / `unsigned`** — applies to `char` and any integer type.
- `unsigned`: only 0 and positive. An 8-bit unsigned goes 0 to 255.
- `signed`: splits the same range across negative integers and whole numbers (meaning including zero). An 8-bit signed goes −128 to 127. Note: one extra negative — not symmetric, because zero takes a place.
- Plain `char` — whether it's signed or unsigned depends on the machine. But ASCII printable characters (0–127) are always positive either way, so no issue there.

**`long double`** — extended precision floating-point. Third size beyond `float` and `double`. Exact size is implementation-defined.

Only valid qualifier combos on floating-point:

| | `float` | `double` |
|-|---------|----------|
| `long` | ✗ | ✓ (`long double`) |
| `short` / `signed` / `unsigned` | ✗ | ✗ |

## 3. Constants

1. integer constant like 1234 is int.
2. 123456789L is long, l or L.
3. unsgined constants terminate with U or u.
4. unsigned long with UL or ul.

5. Floating-point constants contain a decimal point (123.4) or an exponent (1e-2, means 1x10^-2) or both; their type is double, unless suffixed. The suffixes f or F indicate a float constant; l or L indicate a long double.

6. Character constants - within single quotes; dependent on the character set of the machine, usually ASCII. It is a number under the hood.
7. String contants - within double quotes. It is an array under the hood;
[Escape sequences can be put in both single and double quotes]

> Note: Technically, a string constant is an array of characters. The internal representation of a string has a null character '\0' at the end, so the physical storage required is one more than the number of characters written between the quotes. There is no limit to how big a string constant can be, but a program must scan it fully to determine its full size, stopping the scan when encounters '\0' null character.
> Note: Standard lib <string.h> function strlen(s) returns the full length of the string argument s, exluding the '\0'.
